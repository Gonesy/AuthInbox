- 保留所有现有 DOM 元素、文字、事件处理、API 请求和 HTML 预览沙箱。

## 保留现有数据和设置的部署方式

本次没有数据库结构变更，不需要新增迁移或重新初始化。

1. 使用当前生产环境原有的 Wrangler 配置和同一个 Cloudflare 账号。确认 Worker 名称、D1 `database_id`、可选 `OAUTH_KV` ID、域名/路由及 `ASSETS` 绑定保持原值。**不能把仓库的示例配置当成生产配置。**
2. 如需发布前备份，使用现有 D1 数据库导出功能；备份含邮件及设置等私有内容，不要提交 Git。
3. 在上述生产配置已经恢复的项目目录中执行：

   ```sh
   pnpm install --frozen-lockfile
   pnpm run build:web
   pnpm exec wrangler deploy --keep-vars
   ```

   `--keep-vars` 保留未在配置中声明的线上环境变量；配置中显式声明的值仍须与生产一致。Wrangler 部署不会删除 Secrets。数据库和 OAuth 数据的保留依赖于继续绑定原来的 D1/KV。

4. 这次样式发布不需要执行 `db:migrate:remote`。仓库原有 `pnpm run deploy` 和 GitHub 部署工作流包含远程迁移步骤；本次没有修改它们，采用上面的直接部署命令可避免执行与 UI 更新无关的迁移。
5. 发布后用原账号登录，对照已有邮件、用户授权、API Keys、通知配置和正则规则；再用手机检查页面切换、表格横向滚动、详情与复制功能。出现异常时恢复发布前的 Worker/静态资源版本，继续使用同一个 D1/KV，无需更改数据库。

本次仅提交 UI 修改与验证说明；Cloudflare 由维护者自行部署。开发与验证过程中未读取、修改或备份线上数据。
